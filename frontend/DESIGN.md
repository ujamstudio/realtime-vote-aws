# MT Vote — Frontend 디자인 설계도

본 문서는 음악 프로그램 실시간 투표 웹의 시각/인터랙션 설계 명세이며, 현재 구현된 [VotePage.tsx](src/pages/VotePage.tsx) / [AdminDashboard.tsx](src/pages/AdminDashboard.tsx)를 정식 디자인 시스템 형태로 정리한 것이다. 향후 확장 시에도 이 문서를 단일 진실 공급원(SSOT)으로 사용한다.

---

## 1. 디자인 원칙

| 원칙 | 의미 | 결정에 미치는 영향 |
|---|---|---|
| **Stage-Friendly** | 스튜디오 조명 환경, 짧은 광고 컷 사이의 빠른 의사결정 | 다크 베이스 + 고채도 액센트 1색, 화면 안에 시각적 결정점 ≤2개 |
| **Thumb-First** | 응원봉을 든 한 손 사용 가정 | 주요 액션은 화면 하단 60%, 터치 타겟 ≥56pt |
| **Optimistic** | 네트워크 200ms 미만의 체감 만들기 | 클릭 즉시 상태 반영, 서버 응답 후 검증/롤백 |
| **Reset-Safe** | 라운드 전환이 곧 컨텍스트 초기화 | 버전(`round_id`)을 UI 상태 키로 사용, 이전 라운드 잔재가 노출되지 않도록 |

## 3. 타이포그래피

```
Font Stack: -apple-system, BlinkMacSystemFont, "Pretendard", "Segoe UI", sans-serif
```

`Pretendard`를 옵셔널로 두어 한글 가독성을 확보하되 미설치 환경에서는 시스템 폰트로 폴백.

| 토큰 | size / line | weight | 용도 |
|---|---|---|---|
| `display` | 32 / 40 | 700 | 대시보드 큰 숫자 |
| `h1` | 22 / 28 | 700 | 페이지 헤더 |
| `h2` | 18 / 24 | 600 | 후보 이름 |
| `body` | 16 / 24 | 400 | 본문 |
| `caption` | 14 / 20 | 500 | 라운드 메타, 도움말 |
| `mono-num` | tabular nums | 600 | 점수 카운터 (자릿수 흔들림 방지) |

점수 표시는 반드시 `font-variant-numeric: tabular-nums`를 적용하여 숫자가 바뀔 때 좌우로 튀지 않게 한다.

## 4. 스페이싱 / 그리드 / 라운드

### 4.1 Spacing scale (4px 기반)

```
xs  4    sm  8    md 12    lg 16    xl 24    2xl 32    3xl 48
```

### 4.2 Radius

```
sm  8    md 12    lg 16    pill 999
```

- 후보 버튼: `lg(16)` — 카드처럼 보이되 너무 부드럽지 않게
- 점수 카드: `md(12)`
- 토스트, 상태 pill: `pill(999)`

### 4.3 모바일 그리드

- 컨테이너: `max-width: 480px`, `padding: 24px 16px`
- 후보 버튼: 단일 컬럼, 세로 간격 `12px`
- 후보가 6명 이상이고 이름이 짧을 때만 2열 허용 (현재 미구현, 향후 옵션)

### 4.4 데스크톱 그리드 (관리자)

- 컨테이너: `padding: 24px`, fluid full-width
- 차트 영역: `flex: 1`, `min-height: 400px`
- 점수 카드: `repeat(auto-fit, minmax(200px, 1fr))`

## 5. 컴포넌트 라이브러리

### 5.1 Candidate Button (모바일 핵심 컴포넌트)

```
┌─────────────────────────────────────────┐
│  후보 A                              ⓘ  │   ← 56pt 높이, padding 20×16
└─────────────────────────────────────────┘
   ↑                                    ↑
   text(18/24, 600)                     상태 슬롯
                                        (idle/spinner/check)
```

| 상태 | 시각 변화 |
|---|---|
| idle | `bg: --panel`, border 투명 2px |
| hover/touch-active | `transform: scale(0.98)`, border `--accent` |
| selected (제출 중) | border `--accent`, 우측에 spinner |
| disabled | `opacity: 0.5`, 커서 변화 없음 (모바일이라) |
| submitted | border `--success`, 우측에 ✓ (1.2초 후 토스트로 전환) |

**필수 스펙**
- 터치 타겟 56pt (Apple HIG / Material 권장 ≥44pt 초과)
- `:active` 시 `transform: scale(0.98)` 50ms — 클릭감
- iOS Safari `:active` 누락 이슈 대응으로 `-webkit-tap-highlight-color: transparent` 후 직접 스타일

### 5.2 Status Pill (대시보드 LIVE 뱃지)

```
● LIVE        (success bg)
연결 중...     (panel-2 bg, gray)
재연결 중      (warning bg, amber)
오프라인       (danger bg)
```

- `padding: 4px 12px`, `font-size: 12px`, `border-radius: pill`
- LIVE 상태에서만 `●` 점멸 애니메이션 (`opacity 0.4↔1, 1.2s`)

### 5.3 Score Card (대시보드 카드)

```
┌──────────────┐
│ 후보 A       │  ← name (caption, --muted)
│              │
│  1,238       │  ← score (display, --text, tabular-nums)
└──────────────┘
```

점수 변경 시 `1238 → 1239` 카운터 애니메이션 (200ms ease-out, 자릿수 ±10 이내일 때만).

### 5.4 Bar Chart (Recharts)

- Bar fill: 후보별 카테고리 컬러
- Bar radius: `[8, 8, 0, 0]` (위쪽 모서리만 둥글게)
- Grid stroke: `--panel-2`, dasharray `3 3`
- Tooltip: `--panel` 배경, `--panel-2` 보더, 1px

### 5.5 Toast

```
        ┌──────────────────────────┐
        │  투표가 접수되었습니다     │
        └──────────────────────────┘
                   ↑
                bottom: 32px, 중앙 정렬
                fade-in 200ms, 3초 후 fade-out
```

### 5.6 Spinner

- 18×18, border 2px, top-color `--accent`, `0.8s linear infinite`
- 후보 버튼 우측에 인라인 배치

### 5.7 Loading Skeleton (예약, 향후 추가)

라운드 정보를 처음 fetch하는 1초 동안 후보 4명 분량의 회색 블록 표시. 레이아웃 점프 방지.

## 7. 인터랙션 / 애니메이션

| 위치 | 트리거 | 애니메이션 | 시간 |
|---|---|---|---|
| 후보 버튼 | `:active` | `scale(0.98)` | 50ms |
| 후보 버튼 | 선택 → 제출 | border 색 전환 | 150ms |
| 토스트 | 등장 | translateY(8px → 0) + fade-in | 200ms |
| 토스트 | 퇴장 | fade-out | 200ms (3초 노출 후) |
| 점수 카운터 | 값 변경 | 카운트업 | 200ms ease-out |
| 차트 막대 | 값 변경 | Recharts 자체 | 300ms (라이브러리 기본) |
| LIVE 점 | 항시 | opacity 펄스 | 1.2s loop |

전반적으로 **150–300ms**를 넘기지 않는다 — 1Hz 업데이트 주기와 충돌 방지.

## 10. 향후 확장 고려사항

### 10.1 후보 사진 지원

CandidateButton에 좌측 56×56 원형 썸네일 슬롯 추가:

```
┌────────────────────────────────┐
│ ⬤  후보 A                       │
└────────────────────────────────┘
```

- 데이터 모델에 `image_url` 필드 추가
- 이미지는 CloudFront에 함께 업로드, 64×64 + 128×128 두 가지 사이즈 (`srcset`)
- 라운드 시작 5초 전 preload

### 10.2 라운드 카운트다운

투표 마감이 정해진 라운드라면 화면 상단에 `0:43` 형식의 카운트다운 표시. 5초 이하 시 색상 `--warning`, 마감 시 자동 done 상태 전환.

### 10.3 투표 결과 공개 모드

라운드 종료 후 모바일에도 막대그래프를 보여줄지 여부. 별도 라우트 `/vote/result` 권장 — 투표 화면과 결과 화면의 컨텍스트를 섞지 않는다.

### 10.4 다국어 (i18n)

현재 한글 하드코딩. 향후 `react-i18next` 도입 시 키 네이밍:

```
vote.title           "실시간 투표"
vote.toast.submitted "투표가 접수되었습니다"
vote.error.network   "일시적인 오류"
admin.title          "실시간 집계 대시보드"
admin.status.live    "LIVE"
admin.status.connecting "연결 중..."
```

### 10.5 진행자용 제어판

`/admin` 화면에 라운드 리셋 버튼/후보 등록 폼을 인라인으로 노출할지 결정 필요. 노출한다면 전용 인증(IAM 또는 단일 토큰) 선행 조건.
